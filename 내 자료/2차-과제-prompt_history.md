# ToDoApp 프롬프트 히스토리 및 진행 내용

본 문서는 개발 과정에서 사용자가 입력한 모든 프롬프트(명령)와 그에 따른 주요 구현 내용을 기록한 문서입니다.

## 📌 프롬프트 1: 프로젝트 초기 기획 및 설계
- **프롬프트**: "바이브 코딩 입문자를 위한 'ToDoApp' 웹을 빌드하기 위한 기술 명세서를 작성하세요. 필수 기능: Todo 입력, 추가, 빈 값 방지, 목록 표시, 완료/미완료 변경, 삭제, 추가·완료·삭제 후 화면 갱신, 기본 UI 구성. 1단계: 추가/삭제, 2단계: 완료 체크, 3단계: 자동 저장. 기술 스택은 HTML, CSS, JavaScript로 하세요"
- **진행 내용**: 요구사항에 맞춰 기능 8개와 3단계 로직을 정의한 `implementation_plan.md` 기술 명세서 작성 및 초기 프리미엄 다크 테마 HTML/CSS/JS 파일 생성 완료.

## 📌 프롬프트 2: 와이어프레임 구조 반영
- **프롬프트**: "첨부한 이미지와 같은 디자인으로 영역을 구분하세요. 맨 하단 status area (상태 및 개수 표시) 나오게 하세요"
- **진행 내용**: `index.html`에서 Status Area 위치를 맨 하단으로 이동, `style.css`에서 각 영역 하단에 점선(`dashed`) 구분선을 추가하여 와이어프레임 디자인과 일치시킴.

## 📌 프롬프트 3: 앱 이름 변경
- **프롬프트**: "이 앱의 이름을 What the Ping! 으로 변경하세요"
- **진행 내용**: 브라우저 탭 `<title>`과 화면 메인 `<header>`의 `<h1>` 텍스트를 "What the Ping!"으로 변경.

## 📌 프롬프트 4: 입문자용 코드 단순화 및 주석 추가
- **프롬프트**: "바이브코딩 입문자를 위한 앱 실습입니다. 초보자가 이해하기 쉽게 필요한 최소 코드로 줄이고 각 섹션이나 각 줄의 역할을 한글 주석을 상세히 달아주세요. 그리고 초보자의 코딩에 대한 이해를 돕기 위해 수정을 할 수 있는 부분을 찾아 제안하세요. 참고로, 내가 명령하는 프롬프트들은 모두 최종 문서에 정리를 해야합니다. 이를 염두에 두고 내가 제시한 프롬프트를 잘 저장하세요"
- **진행 내용**: 
  - 복잡한 그래픽 효과(블랍, 유리 질감)를 제거하고 가장 직관적인 HTML 태그와 CSS로 구조 전면 수정.
  - `app.js`에 DOM 선택, 상태 관리, 이벤트 연결에 대한 상세한 한글 주석 추가.
  - 초보자가 수정해볼 만한 포인트(placeholder 변경, 버튼 색상 변경 등) 제안 문서화.

## 📌 프롬프트 5: 사용성 개선 (체크박스 확대)
- **프롬프트**: "완료/완료해제 체크박스가 너무 작아서 클릭이 어렵습니다. 박스 크기를 더 키워주세요"
- **진행 내용**: `style.css`에 체크박스 선택자를 추가하여 가로/세로를 20px로 확대하고 텍스트와의 여백(`margin`)을 15px로 늘림.

## 📌 프롬프트 6: 삭제 취소(Undo) 기능 기획 및 구현
- **프롬프트**: "삭제를 잘못해서 되돌리기 하고 싶을 때 누를 수 있는 '삭제 취소' 버튼을 만들려고 합니다. 삭제 취소가 이전 몇단계까지 될지, 어떤 방식으로 될지 plan을 세워서 먼저 보여주고 코드 작성을 기다리세요"
- **진행 내용**: 
  - 최근 5단계까지 복구되는 LIFO(스택) 방식의 기획안 작성 후 승인 대기.
  - 승인 후 `app.js`에 `deletedTodos` 휴지통 배열 추가 및 `undoTodo` 로직 구현.
  - `index.html`에 취소 버튼 추가 및 비활성화 상태(`disabled`) 스타일 구현.

## 📌 프롬프트 7: 초기 디자인(반응형, 다크테마) 복원
- **프롬프트**: "웹화면과 모바일 화면이 동적으로 전환되는 첫번째 디자인이 더 좋았어요. 복잡한 코드와 개념을 사용하지 않고도 첫번째 디자인과 비슷하게 변경할 수 있나요?"
- **진행 내용**: HTML/JS 구조는 그대로 유지한 채 `style.css`만 수정하여 500px 기준 `@media query` 반응형 구현, Outfit 구글 폰트 적용, 호버 애니메이션 추가 등 초창기 프리미엄 느낌의 다크 테마 복원.

## 📌 프롬프트 8: 남은 할 일 개수 실시간 표시
- **프롬프트**: "남은 할 일 개수를 실시간으로 표시하는 기능을 넣으세요"
- **진행 내용**: 하단 Status Area에 남은 개수 표시 영역 추가 및 `app.js` 렌더링 로직에 `total - doneCount` 계산 후 출력하는 기능 반영.

## 📌 프롬프트 9: 상태별 필터링 기능 추가
- **프롬프트**: "기존 코드에 영향을 주지 말고 상태별 필터링 (전체/진행/완료) 구분 하세요"
- **진행 내용**: `index.html`에 3개의 필터 버튼 추가. `app.js`의 원본 데이터 수정 없이 `render()` 내부에서만 데이터를 필터링(`filteredTodos`)하여 렌더링하는 안전한 로직으로 구현.

## 📌 프롬프트 10: 영구 저장 방식에 대한 질문
- **프롬프트**: "locastorage 데이터 영구 저장 기능을 넣기위해서는 어떤 방법이 있나요?"
- **진행 내용**: 로컬 스토리지의 한계를 설명하고, 초보자가 시도하기 좋은 진정한 영구 저장 방법으로 클라우드 BaaS(Firebase, Supabase) 및 백엔드(서버/DB) 구축 방법 안내.

## 📌 프롬프트 11: 할 일 내용 수정 기능
- **프롬프트**: "todo 내용 수정 기능을 구현하세요"
- **진행 내용**: 입문자 눈높이에 맞춰 브라우저 내장 `prompt()` 창을 이용해 내용을 수정하고 원본 데이터를 변경 및 재렌더링하는 수정 버튼 추가 완료.

## 📌 프롬프트 12 & 13: 라이트/다크 모드 토글 (아이콘화)
- **프롬프트 12**: "dark mode / light mode 토글 버튼을 제작하세요"
- **프롬프트 13**: "라이트모드/다크모드 글자를 빼고 아이콘으로만 나오게 하세요"
- **진행 내용**: 
  - 우측 상단에 둥근 아이콘 전용 토글 버튼 추가(`☀️/🌙`).
  - `style.css`에 `body.light-mode` 속성을 추가하여 화이트/밝은 회색 테마 덮어쓰기 구현.
  - 상태 전환 로직 및 사용자 테마 취향을 로컬 스토리지에 영구 저장하는 로직 적용.

## 📌 프롬프트 14: 레이아웃 안정성 개선 (상단 정렬)
- **프롬프트**: "전체보기 / 진행중 / 완료됨 : 전환시 상하 정렬이 중간으로 돼서 위쪽 여백이 변해 불안정해 보입니다. 상하 정렬을 중앙 정렬에서 상단 정렬로 변경 가능한가요?"
- **진행 내용**: `body`의 `align-items`를 `center`에서 `flex-start`로 변경하고, `padding-top: 8vh`를 추가하여 아이템이 줄어들어도 앱 상단 위치가 흔들리지 않도록 수정.

## 📌 프롬프트 15: Git 기록 (현재 진행 중)
- **프롬프트**: "진행 내용을 git에 기록해주세요 (프롬프트 포함)"
- **진행 내용**: 본 `prompt_history.md` 문서를 작성하고, 저장소를 Git으로 초기화(`git init`)하여 모든 변경 사항을 첫 번째 커밋으로 기록 완료.
