\# GitHub Finder 리팩토링 구현 계획: OOP 및 상태 기반 아키텍처 도입



강사님의 피드백을 반영하여, 현재의 함수형 구조를 \*\*상태(State) 중심의 객체지향(OOP) 구조\*\*로 리팩토링합니다. 이를 통해 코드의 가독성, 유지보수성, 확장성을 높입니다.



\## 사용자 리뷰 필요 사항



> \[!IMPORTANT]

> - 기존 `app.js`를 완전히 새로운 구조로 재작성할 예정입니다.

> - 상태 관리 라이브러리 없이 순수 자바스크립트(Vanilla JS)의 클래스와 `Proxy` 또는 간단한 `Pub/Sub` 패턴을 사용하여 상태 기반 렌더링을 구현합니다.



\## 핵심 개선 방향



1\. \*\*상태(State) 중심 설계\*\*: 화면의 모든 변화는 데이터 상태(`state`)의 변화로부터 시작됩니다. UI 함수를 직접 호출하는 대신, 상태를 업데이트하면 UI가 자동으로 반응하도록 구성합니다.

2\. \*\*객체지향(OOP) 도입\*\*: 역할을 기준으로 클래스를 분리합니다.

&#x20;  - `Store`: 앱의 전체 상태 관리

&#x20;  - `GithubService`: API 통신 전담

&#x20;  - `Component`: UI 렌더링 기초 클래스 및 개별 컴포넌트(Profile, Repo, Chart 등)

&#x20;  - `App`: 앱 초기화 및 이벤트 바인딩 조율



\---



\## 상세 변경 사항



\### 1. \[NEW] `githubService.js` (또는 `app.js` 내 모듈 분리)

API 호출 로직을 전담하는 클래스를 생성합니다.

\- `getUserProfile(username)`: 유저 정보 조회

\- `getUserRepos(username)`: 레포지토리 정보 조회



\### 2. \[NEW] `store.js` (상태 관리 클래스)

앱의 데이터 상태를 저장하고 변경을 감지합니다.

\- 관리할 상태: `user`, `repos`, `isLoading`, `theme`, `error`

\- 상태 변경 시 등록된 리스너(UI 컴포넌트)들에게 알림을 보냅니다.



\### 3. \[MODIFY] `app.js` (컴포넌트화 및 메인 로직)

기존 함수들을 클래스 기반 컴포넌트로 전환합니다.

\- `Component`: 공통 UI 렌더링 로직을 담은 베이스 클래스

\- `ProfileView`, `ReposView`, `ChartView`: 각 영역의 렌더링 전담

\- `SearchView`: 검색창 및 이벤트 처리

\- `ThemeManager`: 테마 변경 및 영구 저장 관리



\### 4. \[MODIFY] `index.html`

\- 필요 시 스크립트 로딩 방식을 `type="module"`로 변경하여 파일 분리를 지원합니다. (또는 하나의 파일 내에서 클래스를 정의합니다.)



\---



\## 구현 단계



1\. \*\*상태 클래스(`Store`) 구현\*\*: 데이터의 흐름을 중앙화합니다.

2\. \*\*컴포넌트 추상화\*\*: `render()` 메서드를 가진 기본 컴포넌트 구조를 설계합니다.

3\. \*\*API 서비스 클래스 구현\*\*: 비동기 데이터를 가져오는 로직을 캡슐화합니다.

4\. \*\*이벤트 핸들러 연결\*\*: 사용자 입력이 상태를 변화시키도록 연결합니다.

5\. \*\*테마 및 차트 연동\*\*: 상태 변화(Theme)에 따라 차트가 파괴되고 재렌더링되는 로직을 상태 구독 방식으로 변경합니다.

바이브코딩 강사님의 피드백을 반영하여, GitHub Finder 앱을 객체지향 프로그래밍(OOP) 및 상태(State) 기반 아키텍처로 리팩토링하기 위한 세부 계획을 수립했습니다.

강사님께서 제안하신 "상태 기반 화면 렌더링"과 "클래스를 활용한 상태 및 메서드 관리"를 핵심 목표로 설정하였습니다.

상세한 계획은 아래 생성된 **구현 계획서(Implementation Plan)**를 확인해 주시기 바랍니다.

implementation_plan.md

주요 리팩토링 포인트:
중앙 집중식 상태 관리: Store 클래스를 도입하여 모든 데이터(유저 정보, 저장소, 테마, 로딩 상태 등)를 한곳에서 관리합니다.
컴포넌트 기반 UI: 각 화면 영역(프로필, 차트, 저장소 등)을 독립된 클래스로 분리하고, 상태가 변경될 때만 자신의 영역을 다시 그리도록 설계합니다.
서비스 레이어 분리: API 통신 로직을 GithubService 클래스로 캡슐화하여 비즈니스 로직과 UI 로직을 엄격히 분리합니다.
지시하신 대로 현재는 코딩을 진행하지 않고 승인을 기다리겠습니다. 계획안을 검토해 보시고 수정이 필요하거나 보완할 점이 있다면 말씀해 주세요! 승인해 주시면 바로 작업을 시작하겠습니다.
